# agent-intent-gate

一个零依赖的「意图 + 交付授权」门，用来回答 Agent 工具层的两个问题：

1. **这一轮该不该动手？**（用户是在问问题 / 要方案，还是明确让执行）
2. **这一次该不该放行？**（技能会改环境、会凭空造新文件时，用户到底授权了没有）

它来自一个真实产品的工单：Agent 反复说「我做不到 / 要我现在整理吗」，用户连说几次
「把这份诊断报告存成 Word 文件」，文件一次都没生成。根因不是模型不想做，而是**两道门的判据
都漏掉了这句话**，于是「验收要求产物、权限门禁止写文件」形成了一个死锁。

这个仓库把解法和最小实现抽出来，可以单独跑、单独测。

## 死锁是怎么形成的

| 环节 | 发生的事情 |
|---|---|
| 用户说 | 「把这份诊断报告存成 Word 文件」 |
| ① 意图判定 | 句子里有「诊断/报告」→ 被判成 **DIAGNOSE（只读调查）** → 写文件技能不放行 |
| ② 交付授权门 | 没有「帮我/给我」前缀，也没有「写一份」这样的「动词+量词」→ 判成「用户没让做」→ 再拦一道 |
| ③ 模型 | 把「被拦」翻译成一句人话：「要我现在整理成一份文案吗？你回我一句就放行」 |
| ④ 用户照说 | 说的还是那句「把这份诊断报告存成 Word 文件」→ 命中同一个洞 → 继续被拦 |
| ⑤ 收尾 | 产物验收要求「必须有文件」，但文件从来没有被允许生成 → 永远 0 项通过 |

**教训：验收标准和权限门必须读同一份「交付授权」事实，否则它们会在用户看不到的地方互相否定。**

## 解法：一条「落成文件」的结构判据

不猜意图，只认结构：**落盘动词 + 文件类名词**，两者相距不超过 12 字、不跨句。
命中即进入新档位 `artifact-save`，意图模式判为 `EXECUTE`，交付授权门同源放行。

- 落盘动词：存成 / 存为 / 保存成 / 保存为 / 另存为 / 存到 / 保存到 / 写到 / 写入 / 写成 /
  导出成 / 导出为 / 导出到 / 输出成 / 输出为 / 输出到 / 整理成 / 做成 / 转成
- 文件类名词：文件 / 文档 / 报告 / 表格 / 文案 / 清单 / 方案 / 总结 / Word / PDF / Excel /
  PPT / TXT / Markdown / md / 图片 / 照片 / 截图 / 常见扩展名

两条安全边界（都写进了测试）：

1. **问原因不等于让我写**。句中出现真疑问词（为什么/怎么/是否/什么…）时不走这条：
   「为什么存成文件会失败？」仍然只是只读调查 / 提问（DIAGNOSE / QUESTION），不会被 `artifact-save` 放行。
2. **不改既有契约**。动词表刻意不含「生成」：「生成一个活动说明文档」继续由既有的
   「动词+量词」判据负责，档位保持原来的 `default-execute`。

## 快速开始

需要 Node.js ≥ 18。

```bash
npm test
node src/demo.mjs "把这份诊断报告存成 Word 文件"
node src/demo.mjs "为什么存成文件会失败？"
```

`demo.mjs` 输出该句的意图模式、理由、是否获得交付授权，以及模拟一次 `file-write` 时门会不会放行。

## 集成方式（伪代码）

```js
import { classifyIntent, isSkillAllowed, isDeliveryAuthorized, planAuthGate } from './src/intent-gate.mjs';

const intent = classifyIntent(userText);          // { mode, reason, signals }
// 1) 执行前的技能闸门
if (!isSkillAllowed(toolName, intent.mode).allowed) {
  return block('这一轮是' + intent.mode + '，不会改动环境的技能才放行');
}
// 2) 凭空新建交付物时的授权门
const gate = planAuthGate({
  skillName: toolName,
  pathExists: fs.existsSync(targetPath),
  userText,
  alreadyBlocked: taskState.authGateFired.has(toolName),
  alreadyGranted: taskState.deliveryAuthGranted,
  target: targetPath,
});
if (gate.blocked) return block(gate.directive);
// 3) 放行
```

## 设计取舍（都是踩过的坑）

- **`default-execute` 兜底档 ≠ 授权凭据**。兜底表示「什么都没找到」，不能拿来证明「用户让我做」；
  授权门只认有证据的档位（显式执行 / 祈使请求 / `artifact-save` / 明确点头 / 动词+量词）。
- **只拦一次**。同一任务里同一个技能被拦过一次后，第二次放行——否则用户回了「做吧」也过不去，
  变成反复追问的死循环。
- **覆盖已有文件不归这道门管**。这道门只管「凭空新建」，避免把「改自己的草稿」也拦死。
- **问句要能兜住**。命中「要不要/能不能/是不是」这类反义疑问时，宁可判 QUESTION，也不能判执行。
- **判据要能被自己打红**。仓库里的测试同时包含正例与反控（问原因、答非所问、陈述过去），
  删掉任何一条判据，对应的测试必须变红。
